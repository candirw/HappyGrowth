# 自定义库存

## 两步

```bash
cp inventory.example.js inventory.js
```

然后只改 `inventory.js`。它已经在 `.gitignore` 里，不会被提交。

页面打开时会先加载 `inventory.example.js`，再加载 `inventory.js`。后者存在就覆盖前者，不存在就静默用示例。

---

## 顶层结构

```js
window.BAR_CONFIG = {
  storagePrefix: 'cj',      // localStorage 键前缀
  spirits: [ ... ],          // 酒瓶
  supplies: [ ... ]          // 辅料
};
```

`storagePrefix` 一般不用改。改了等于换一套全新的空数据。

## 酒瓶 `spirits`

```js
{
  code: 'S01',                          // 编号，自定义，短一点
  name: '伏特加-绝对',                    // 显示名，统一写「品类-品牌」
  covers: ['伏特加'],                    // ★ 关键字段
  type: '伏特加',                        // 品类，悬停显示
  abv: '40%',
  origin: '瑞典',
  taste: '中性、干净，几乎没有杂味……',     // 风味描述
  keep: '常温避光直立，开瓶后 1–2 年稳定', // 保存条件
  warn: false,                          // true 时保存条件用红色警示
  use: '螺丝起子、莫斯科骡子、大都会'        // 常用于
}
```

### `covers` 是唯一会影响判断的字段

它声明"这瓶酒能满足配方里的哪些用料名"。配方里写的是通用名（`伏特加`、`威士忌`），程序靠 `covers` 把你的具体酒瓶对上去。

| 你的酒 | 建议的 covers |
|---|---|
| 某款伏特加 | `['伏特加']` |
| 某款调和威士忌 | `['威士忌']` |
| 某款爱尔兰威士忌 | `['威士忌', '爱尔兰威士忌']` ← 两个都写，两种配方都能命中 |
| 某款龙舌兰 | `['龙舌兰']` |

**判断规则**：`covers` 里只要有一个名字能对上配方用料，就算"有这瓶"。

漏写的后果：对应配方会显示「缺基酒」。不致命，但会让可做数偏低。

### `name` 的命名约定

统一写成 **「品类-品牌」**，中间用半角连字符：

| 写法 | 例子 |
|---|---|
| ✅ 推荐 | `威士忌-尊美醇`、`金酒-孟买蓝宝石`、`苦味利口酒-金巴利` |
| ❌ 避免 | `尊美醇 Jameson`、`孟买蓝宝石金酒`、`S04` |

好处是在下拉列表和库存芯片里一眼能看出这是什么酒，不用记品牌属于哪个品类。品类名建议和 `type` 字段保持一致。

### code 的命名习惯

供参考，没有强制要求：

| 前缀 | 用途 |
|---|---|
| `S` | 烈酒（Spirit）：伏特加、威士忌、金酒、朗姆、龙舌兰、白兰地 |
| `L` | 利口酒（Liqueur） |
| `V` | 味美思等加强葡萄酒（Vermouth） |
| `W` | 普通葡萄酒 / 起泡酒 |

两位数字顺延即可，`S01`、`S02`……。编号只在程序内部用，不改也不影响。

## 辅料 `supplies`

```js
{
  key: 'lime',              // 内部键名，英文，不要重复
  name: '青柠',              // 显示名
  covers: ['青柠汁'],        // 对应配方里的用料名，可写多个别名
  hint: '现榨，一个出汁 25–30ml',
  def: 'have',              // 初始状态
  optional: false           // 可选：缺了不算"做不了"
}
```

### `def` 三态

| 值 | 含义 | 页面表现 |
|---|---|---|
| `have` | 有 | 绿色 ✓ |
| `none` | 没有 | 红色 ✕ |
| `unknown` | 待确认 | 灰色 ? |

这只是**初始值**。用户在页面里点芯片改过之后，状态存进 localStorage，就不再读 `def` 了。

想重置：浏览器控制台执行 `localStorage.removeItem('cj_supplies_v1')` 后刷新。

### `optional`

给「有了更好、没有也能做」的辅料用，目前只有蛋白（威士忌酸的蛋白是可选项）。

`optional: true` 的辅料即使标成 `none`，也不影响「可做」判定。

### `covers` 写多个别名

同名不同写法时很有用：

```js
{ key: 'bitters', name: '苦精', covers: ['苦精', '安格斯特拉苦精', 'Angostura'] }
```

## 常见问题

**Q：为什么某款显示「缺基酒」，我明明有这瓶？**

`covers` 对不上配方里的用料名。去配方里看那一行的第一个字段写的是什么，然后把它加进 `covers`。

**Q：可以只放几瓶酒吗？**

可以。没放的那些配方会显示「缺基酒」，这是正常表现，不是 bug。

**Q：改了 `inventory.js` 刷新没变化？**

浏览器缓存。按 `Ctrl + F5` 强制刷新。

**Q：能给同一品类放两瓶吗？**

可以，`covers` 都写同一个名字就行，程序会认为是"任一即可"：

```js
{ code: 'S03', name: '孟买蓝宝石', covers: ['金酒'] },
{ code: 'S04', name: '添加利',     covers: ['金酒'] }
```

这样做金酒类配方时，只要有其中一瓶就算可做。想区分用哪瓶，在配方备注里写清楚就行。
