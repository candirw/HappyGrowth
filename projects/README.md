# projects/ · 代码实现（Part 3）

> 点子到可运行代码的产物区。每个子目录是一个独立项目，**状态必须明确**，不允许"说不清状态"的项目长期存在。

## 新建项目

```bash
cp -r projects/_template projects/<项目名>
cd projects/<项目名>
python -m venv .venv            # 每个项目独立环境，不共用
```

然后把 `_template` 里的四个文件按实际情况填：`README.md` / `PLAN.md` / `PROGRESS.md` / `DECISIONS.md`。

## 状态纪律（见 `../DECISIONS.md` ADR-007）

- 每个项目的 `PROGRESS.md` 顶部必须有状态：`设想 | 调研 | 在做 | 暂停(原因) | 完成 | 废弃(原因)`
- **连续 30 天无 commit**，必须显式标为"暂停"或"废弃"并写明原因
- "废弃"是正常状态，不是失败——允许废弃，但不允许"不说清楚"

## 复现类任务 checklist（基于已有实现改造，而非从零写）

```
① fork / clone，先跑通原版，不改任何代码
② 把环境要求记进 PROGRESS.md
③ 明确"跑通"的定义是什么（输出什么才算成功）
④ 只改一行，验证改动生效
⑤ 才开始真正的改造
```
