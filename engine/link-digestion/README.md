# link-digestion（链接消化）

一个可直接被 AI agent 加载的 Skill：把"收到一个链接"变成**有判据、有产出、有留痕**的处理流程。

## 为什么需要它

链接是最高频、也最容易浪费时间的输入。常见失败模式有三种：

1. **全读**——每个链接都拉全文，上下文被灌爆，主线被打断；
2. **全存**——收藏夹越堆越高，从来没回头看，存了等于没存；
3. **全丢**——看完即忘，下次遇到同样问题重新搜一遍。

本 Skill 的做法是把处理成本**按价值分档**：先用 30 秒判断值不值得花 30 分钟，只有少数进入深读。

## 它解决什么

对应本仓库 `PLAN.md` 里的两块能力：

| 环节 | 对应模块 | 作用 |
|---|---|---|
| 甄别（真伪 / 时效） | Part 4 可行性 / 准确性核查 | 在信息进入知识库**之前**做一次拦截 |
| 提取 → 摘要 → 判断 → 去向 | Part 2 外部检索（采集） | 采集结果结构化，而不是原文倾倒 |
| 台账 | Part 1 迷你图书馆的入口 | 每条输入可追溯：谁给的、什么时候、去了哪 |

## 核心结构

```
甄别 → 分诊 → 提取 → 摘要 → 判断 → 去向 → 台账
```

- **分诊四档**：深读 / 扫一眼 / 归档入池 / 看过即可。只有"深读"才拉全文。
- **甄别六信号**：命中 ≥2 条即判定低可信，直接降级。
- **去向四类**：工具推荐、稳定知识、有触发条件、要落地；有副作用的动作（安装、试跑）必须单独确认。
- **台账五列**：日期 / 链接 / 来源作者 / 主题 / 去向。来源字段本身在积累"优质信息源清单"。

完整流程见 [`SKILL.md`](./SKILL.md)。

## 怎么用

**方式一：作为 agent skill 加载**

把 `SKILL.md` 放进所用 agent 的 skills 目录（Claude Code / Hermes / 其他支持 skill 的框架均可），其 frontmatter 的 `description` 决定触发时机。

**方式二：作为流程规范人工执行**

不需要 agent 也能用：把"七步"当检查清单，每次处理链接逐项走一遍。分诊表和甄别信号是最小可用部分。

**方式三：接进采集管线**

若后续 Part 2 做成自动化采集，可在"抓取完成"和"入库"之间插入第 1–2 步（甄别 + 分诊），过滤掉低可信与低价值内容，避免知识库被噪声稀释。

## 接入前要改的地方

`SKILL.md` 顶部有一段 `接入配置`，换环境只改这一段：

- `interest_domains`：判断"相不相关"的锚点，必须按使用者改写，否则分诊失效
- `ledger_path`：台账落盘路径
- `archive_target` / `auto_archive`：归档到哪、要不要逐次确认

其余流程与判据是通用的，不需要改。

## 边界

- 它**不做**内容真实性调查，只做"快速可信度定性"；需要严谨核查时转 Part 4。
- 它**不做**知识库结构设计，只负责把内容送到正确的入口。
- 它**不代替**部署验证；"装/试"之后是否可用，由部署流程验收。
