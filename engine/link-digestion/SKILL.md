# 链接消化（Link Digestion）

把"别人发来一个链接"这个高频小动作，变成一条可复用、可审计的流水线：**甄别 → 分诊 → 提取 → 摘要 → 判断 → 去向 → 台账**。

目标不是"读完"，而是**在正确的地方花正确的力气**：90% 的链接应该 30 秒处理完，只有少数值得拉全文、深读、落地。

---

## 0. 接入配置（换环境只改这一段）

```yaml
interest_domains:        # 判断"相不相关"的锚点，按使用者改写
  - 投资：黄金、美股、A股
  - AI / 技术：AI、游戏、项目制作
  - 学习 / 成长：认知、写作、创作

ledger_path: ./pending-links.md       # 台账落盘位置
archive_enabled: true                 # 稳定知识是否自动归档
archive_target: obsidian              # obsidian | notion | 本地目录 | 不归档
auto_archive: true                    # true=不逐次确认；false=每次问
```

没有配置也能跑，用上面的默认值。

---

## 触发

任何链接 / URL 到达即触发，不需要"帮我消化一下"这种指令。

多个链接连续发来时：**先编号收齐，等"发完了"再统一消化**，避免逐个打断。

## 九环总纲

```
甄别 → 分诊 → 学习 → 评估 → 借鉴 → 关联 → 沉淀 │ 部署 → 验证
（真伪）（值不值）（理解）（价值）（提取）（挂主线）（固化）  （落地）（回看）
```

本 skill 负责**前七环（当场消化）**。后两环在"去向"判定为"要落地"之后，转交给部署/验证流程，不混进"收链接"这个轻动作。

---

## 七步流程

### 1. 甄别（真伪 / 时效）

扫标题 + 前几段即可，**不做全文检索**。命中以下信号 **≥2 条** → 判定低可信：

- 标题党话术（颠覆 / 炸裂 / 秒杀 / 99% 的人不知道）
- 无作者署名、无真实出处，通篇"据了解""业内人士透露"
- 纯观点堆砌，无数据来源、无可核验链接
- 结尾挂"加我微信 / 关注领资料 / 私信进群"
- 技术文却给不出仓库地址、版本号、可复现命令
- 时效存疑：无发布日期，或内容已明显过时

低可信 → 降级为"看过即可"，**不推荐安装、不推荐入库**。

### 2. 分诊（值不值 / 深浅）

在提取全文**之前**，按「现在要不要用 × 可不可信」两维定档：

| 档位 | 判据 | 动作 |
|---|---|---|
| **深读** | 命中兴趣域 + 现在就要用（当前项目 / 具体痛点） | 拉全文，完整摘要 + 判断 + 可能入池 |
| **扫一眼** | 命中兴趣域，但非当前重点 | 2–3 句摘要，不深挖 |
| **归档 / 入池** | 有价值但"以后才用" | 归档或记入灵感池，不现在展开 |
| **看过即可** | 低可信，或纯开阔眼界无行动价值 | 一句话带过，不沉淀 |

只有「深读」档才拉全文，其余三档跳过全文提取——这是省时间的关键。

### 3. 提取

按来源选通路：网页 / 公众号 → 正文抽取；PDF → 直接解析；GitHub → 读 README + 最近提交；登录态平台 → 见下方专节。

### 4. 摘要

3–6 条 bullet，不超过一屏：是什么、核心功能或论点、亮点、短板。

**不回灌全文**，避免污染主线上下文。

### 5. 判断

结合配置的兴趣域给**明确结论**：值得关注 / 值得试用 / 值得归档 / 看过即可。

要具体到使用者的场景，不写"值得关注"这种空话。

### 6. 去向

见下方「去向判定」。

### 7. 台账

追加一行到 `ledger_path`：

| 日期 | 链接 | 来源/作者 | 主题 | 去向 |
|---|---|---|---|---|
| 08-13 | https://… | 宝玉(@dotey) | 某旅行规划工具 | 入灵感池(5/5) |

- 「来源/作者」：作者名 / 公众号名 / 博主名 / 机构名；无署名写"机构号/无署名"（这本身就是负面信号，也是在积累优质信息源清单）。
- 评分只出现在「入灵感池」这一档，其他去向不带分。

## 去向判定

| 内容类型 | 默认去向 |
|---|---|
| **工具 / 资源推荐** | 看过即可，除非有明确使用场景或使用者说"装 / 试" |
| **稳定知识 / 教程** | 自动归档到对应项目；`auto_archive: false` 时先确认 |
| **有触发条件、未来会影响行动** | 拟入灵感池 |
| **要落地的东西** | 先确认目标机器与环境，再走部署流程并验证 |

**装 / 试属于有副作用的动作**，不能只因为"链接里推荐了"就执行。

## 登录态内容源（通用模式）

知乎、公众号、小红书、X 等平台对数据中心 IP 有风控，裸请求常被拦。统一走：

1. **先查登录态**，不要先试裸抓。
2. **验证要看到业务字段**（用户名、ID、正文），不能只看 HTTP 200。
3. **优先第一方 API**，带 cookie 调，比抓网页稳定。
4. **长正文先落盘再解析**，避免大文本进上下文。
5. **cookie 明文不入库、不进日志、不写进文档**；凭证放在独立的 secrets 目录，权限 600。

具体平台的抓取细节按平台文档维护，本 skill 只定这条通用次序。

## Pitfalls

- 平台正文抽取偶发标题为空、图片变占位符，正文仍可用，不必反复重试。
- **推荐语 ≠ 已验证事实**：装之前核对仓库真实状态（star、最近提交、README 的部署方式）。
- 甄别是快速定性，不是查案；不要为低风险链接花大量检索。
- 归档不等于学会：存了没用过的资料，三个月后等于没存。
- 台账不更新，等于整条链路没有留痕，下次重复劳动。

---

## 验收

消化 PASS = 甄别已做 + 分诊已定档 + 摘要已给 + 去向明确 + 台账已更新。

装 / 试类另行走部署验证，不计入"消化 PASS"。
